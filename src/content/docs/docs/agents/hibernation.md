Orca이 유휴 백그라운드 에이전트 터미널을 일시 중지하고 작업 트리를 다시 열 때 자동으로 재개하도록 합니다.

수십 개의 작업 트리를 열어두면 유휴 에이전트가 추가됩니다. 각 에이전트는 메모리에 모델 세션을 보유하는 라이브 PTY입니다. 에이전트 최대 절전 모드를 사용하면 Orca이 해당 터미널이 완료되고 오랫동안 손대지 않은 후 해당 터미널을 조용히 중지한 다음 다음에 작업 트리를 열 때 동일한 세션을 다시 시작할 수 있습니다.

실험적

에이전트 최대 절전 모드는 기본적으로 꺼져 있습니다. 안전 모델을 계속 조정하는 동안 `Settings → Experimental → Agent hibernation`(설정 → 실험적 → 에이전트 최대 절전 모드)에서 이를 켜세요.

## 최대 절전 모드로 전환되는 항목

Orca은 다음 `all`(모두) 해당하는 경우에만 에이전트 터미널을 최대 절전 모드로 전환합니다.

- 에이전트는 `done`(완료) 상태입니다. 마지막 차례를 마쳤으며 입력을 기다리고 있지 않습니다.
- 터미널이 활성 작업 트리 또는 현재 전경 터미널을 렌더링하는 작업 트리에 없습니다.
- 에이전트가 완료된 이후 키 입력을 받지 못했습니다.
- 에이전트가 [재개 가능한 세션](/orca-docs-ko/docs/agents/session-history/): Claude, Codex, Gemini, Antigravity, OpenCode, Droid 또는 Grok을 포함하는 에이전트입니다.
- 구성된 유휴 기간(기본값 30분) 이상 동안 유휴 상태였습니다.
- 현재 단말기를 구동하고 있는 모바일 세션이 없습니다.

검사에 실패한 터미널은 계속 실행됩니다. 작업 트리에 에이전트 창이 여러 개 있는 경우 하나의 단위로 함께 최대 절전 모드로 전환되므로 부분적으로 일시 중지된 작업 트리는 배송되지 않습니다.

## 유휴 창 조정

`Agent hibernation`(에이전트 최대 절전 모드) 토글에서 `Hibernate after`(최대 절전 모드)는 Orca이 일시 중지하기 전에 완료된 백그라운드 에이전트가 대기해야 하는 유휴 시간(분)을 설정합니다.

- 기본값: `30 minutes`(30분).
- 범위: `1 minute`(1분)~`24 hours`(24시간).
- 시계는 에이전트의 마지막 `done` 업데이트부터 시작됩니다. 키 입력, 새 출력 또는 에이전트의 터미널 탭으로 돌아가면 재설정됩니다.

창을 길게 사용하면 일시 중지 횟수가 줄어들어 메모리가 절약됩니다. 창이 짧을수록 더 적극적으로 일시 중지되지만 다음에 다시 전환할 때 다시 시작하는 데 비용이 듭니다.

## 잠자는 작업 트리 찾기

사이드바 필터 메뉴는 휴면 작업 트리 표시 여부를 제어합니다. 자주 숨기는 경우 [설정 → 바로가기](/orca-docs-ko/docs/settings/)에서 `Toggle Sleeping Workspaces`(잠자기 작업공간 전환)을 지정하면 필터 메뉴를 열지 않고도 표시하거나 숨길 수 있습니다.

## 재개 중

최대 절전 모드 작업 트리를 열면 Orca은 [에이전트 세션 기록](/orca-docs-ko/docs/agents/session-history/) - `claude --resume <id>`, `codex resume <id>` 등에서 사용하는 것과 동일한 재개 플래그를 사용하여 에이전트 CLI를 다시 시작합니다. 따라서 대화, 작업 디렉터리 및 공급자 세션은 중단된 위치부터 시작됩니다. 클릭할 것이 없습니다. 재개는 터미널을 다시 전경으로 가져오는 과정의 일부로 발생합니다.

또한 재개는 Orca이 처음 에이전트를 열 때 캡처된 시작 명령, 인수 및 개인 환경을 재사용합니다.

어떤 이유로든 에이전트 CLI가 세션을 재개할 수 없는 경우(기록이 삭제되었거나 공급자가 세션 ID를 교체함) 터미널이 새로운 프롬프트로 열리고 이전 기록은 에이전트의 세션 기록에서 계속 사용할 수 있습니다.

## 제한사항

나열된 재개 가능한 에이전트만 최대 절전 모드로 전환됩니다. Cursor CLI, Hermes, Pi, Copilot 및 기타 재개할 수 없는 터미널은 계속 실행 중입니다.
