Cmd-J 범위는 작업 트리, 최근 항목 및 탭 간에 이동합니다.

작업 트리 수가 너무 많으면 탐색으로 인해 병목 현상이 발생합니다. Orca은 두 가지 키보드 우선 탐색 도구를 제공합니다.

## 빠른 열기(Cmd-P)

현재 작업 트리로 범위가 지정된 파일 검색입니다. 조각을 입력하세요. Orca은 최근성과 일치 점수를 기준으로 순위를 매기고 새 편집기 탭에서 파일을 엽니다. Gitignored 파일은 결과에 포함됩니다. 일치 항목을 추적한 후 두 번째 패스로 표시되므로 자주 빠르게 여는 파일(빌드 출력, 환경 파일)은 목록 상단을 오염시키지 않고 계속 접근할 수 있습니다.

## 워크트리 점프 팔레트(Cmd-J)

한 번의 검색으로 모든 작업 트리와 모든 탭을 뛰어넘을 수 있습니다. 빈 입력의 자리 표시자는 *repo/worktree*을 읽습니다. 그에 따라 절반 및 Orca 필터를 입력합니다. 입력을 시작하면 사이드바의 현재 필터에 의해 숨겨지더라도 보관되지 않은 작업 트리가 검색에 포함됩니다.

팔레트에서 **`Tab`(Tab 키)**을 누르면 호스트 및 프로젝트 필터 메뉴가 열립니다. 선택한 호스트와 프로젝트에 따라 결과 범위가 좁아지고, 선택 항목은 하나씩 제거할 수 있는 칩으로 표시됩니다. 팔레트를 닫으면 필터가 지워지므로 다음에 열 때는 범위가 지정되지 않습니다.

결과에는 다음이 포함됩니다.

- `Recent Worktrees`(최근 작업 트리) — 검색어가 비어 있을 때 표시되는 최상단 섹션입니다. 마지막으로 포커스한 순서로 정렬되며 목록을 쉽게 훑어볼 수 있도록 항목 수가 제한됩니다.
- 프로젝트와 저장소 그룹을 통해 이름으로 사이드바 섹션으로 이동합니다.
- 입력을 시작하면 모든 작업 트리가 저장소별로 그룹화됩니다.
- 리뷰 메타데이터가 이미 있으면 캐시된 GitHub PR 제목 또는 번호(`#123`)와 캐시된 GitLab 병합 요청 제목 또는 번호(`!123`)로 작업 트리를 찾습니다.
- 열려 있는 모든 탭이 먼저 현재 작업 트리 범위로, 그다음 전체 범위로 표시됩니다.

작업 트리에서 `Shift-Enter`를 누르면 현재 창을 바꾸는 대신 새 분할 창에서 엽니다.

검색어가 기존 작업 트리와 일치하지 않으면 팔레트에 입력한 텍스트를 이름으로 사용하는 **`Create worktree`(작업 트리 만들기)** 행이 표시됩니다. 기존 일치 항목이 먼저 선택된 상태로 유지되므로 실제 결과가 있을 때 `Enter`를 누르면 계속 해당 항목으로 이동합니다.

바로가기 바인딩은 [설정 → 바로가기](/orca-docs-ko/docs/settings/)에서 다시 매핑할 수 있습니다.
