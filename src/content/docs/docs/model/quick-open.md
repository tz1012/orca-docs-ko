Cmd-J 범위는 작업 트리, 최근 항목 및 탭 간에 이동합니다.

작업 트리 수가 너무 많으면 탐색으로 인해 병목 현상이 발생합니다. Orca은 두 가지 키보드 우선 탐색 도구를 제공합니다.

## 빠른 열기(Cmd-P)

현재 작업 트리로 범위가 지정된 파일 검색입니다. 일부 텍스트를 입력하면 Orca이 최근성과 일치 점수를 기준으로 순위를 매기고 새 편집기 탭에서 파일을 엽니다. 결과 행에는 **파일 이름**이 먼저 표시되고 공간이 부족하면 상위 디렉터리가 잘립니다. 마우스를 올리면 전체 경로가 표시됩니다. Gitignored 파일도 결과에 포함되며, 추적된 일치 항목 다음의 두 번째 단계에서 표시됩니다. 따라서 자주 빠르게 여는 파일(빌드 출력, 환경 파일)에 계속 접근할 수 있으면서 목록 상단은 복잡해지지 않습니다.

## 새 탭 옴니박스(+)

탭 표시줄의 **+** 옴니박스는 **열린 탭**, 파일, URL 및 에이전트를 한 필드에서 검색합니다(자리 표시자: *`Search open tabs, files, URLs, agents…`(열린 탭, 파일, URL, 에이전트 검색…)*). 파일 행은 빠른 열기와 동일하게 파일 이름을 먼저 표시합니다. 이미 열린 편집기 탭과 일치하면 중복 파일 결과보다 해당 탭을 우선하므로, 파일을 두 번째로 열지 않고 열린 버퍼로 이동합니다.

경로나 URL 대신 웹 검색어를 입력하면 작업 트리 브라우저에서 [**`Default Search Engine`(기본 검색 엔진)**](/orca-docs-ko/docs/settings/)으로 검색 결과를 엽니다. 토큰이 하나뿐이면 파일 일치 항목을 계속 우선하고, 여러 단어로 된 구문이면 검색 행을 위로 올립니다. 파일 및 탭 일치 과정을 건너뛰고 즉시 검색하려면 검색어 앞에 `?`을 붙입니다.

## 워크트리 점프 팔레트(Cmd-J)

한 번의 검색으로 모든 작업 트리와 모든 탭을 오갈 수 있습니다. 빈 입력의 자리 표시자에는 *repo/worktree*이 표시됩니다. 어느 쪽이든 입력하면 Orca가 그에 맞게 필터링합니다. 입력을 시작하면 사이드바의 현재 필터에 의해 숨겨진 보관되지 않은 작업 트리도 검색에 포함됩니다. Slack 형식 이모지 단축 코드(`:rocket:`)는 작업 공간 이름을 지정할 때와 동일한 제안 팝오버를 사용합니다.

팔레트에서 **`Tab`(Tab 키)**을 누르면 호스트 및 프로젝트 필터 메뉴가 열립니다. 선택한 호스트와 프로젝트에 따라 결과 범위가 좁아지고, 선택 항목은 하나씩 제거할 수 있는 칩으로 표시됩니다. 팔레트를 닫으면 필터가 지워지므로 다음에 열 때는 범위가 지정되지 않습니다.

결과에는 다음이 포함됩니다.

-   **`Recent Chats & Terminals`(최근 채팅 및 터미널)** — 검색어가 비어 있으면 최근 agent/terminal 세션을 활동 순서에 따라 최대 6개 표시합니다. 확인 필요, 완료, 유휴 순으로 정렬됩니다. 현재 보고 있는 유휴 탭은 목록을 실행 가능하게 유지하기 위해 제외되지만, 현재 탭이 작업 중이거나 사용자 응답을 기다리거나 읽지 않은 활동이 있으면 계속 표시됩니다. 각 행에는 탭 표시줄과 동일한 실시간 주의 배지(스피너, 물음표, 벨, 확인 표시)가 나타납니다. 숫자 바로 가기(macOS의 `Cmd-1`–`Cmd-6`, Windows/Linux의 `Ctrl-1`–`Ctrl-6`)를 누르면 해당 행으로 바로 이동합니다. 팔레트가 열리면 항목과 순서가 고정되어 포인터 아래에서 행이 바뀌지 않습니다.
-   **`Recent Worktrees`(최근 작업 트리)** — 검색어가 비어 있을 때 다음으로 표시되는 섹션입니다. 마지막 포커스 순서로 정렬되며 목록을 쉽게 훑어볼 수 있도록 항목 수가 제한됩니다.
-   프로젝트와 저장소 그룹을 통해 이름으로 사이드바 섹션으로 이동합니다.
-   입력을 시작하면 모든 작업 트리가 저장소별로 그룹화됩니다.
-   리뷰 메타데이터가 이미 있으면 캐시된 GitHub PR 제목 또는 번호(`#123`)와 캐시된 GitLab 병합 요청 제목 또는 번호(`!123`)로 작업 트리를 찾습니다.
-   열려 있는 모든 탭이 먼저 현재 작업 트리 범위로, 그다음 전체 범위로 표시됩니다. `terminal` 또는 `simulator` 같은 유형 별칭도 행 레이블을 복잡하게 만들지 않으면서 해당 탭 유형과 계속 일치합니다.

입력한 검색어가 열린 탭과 작업 트리에 **모두** 일치하면, 팔레트는 어느 주요 목록도 묻히지 않도록 각 섹션의 짧은 미리 보기를 번갈아 표시합니다(*`N more — scroll or keep typing`(N개 더 있음 — 스크롤하거나 계속 입력)* 안내 포함). 한 섹션에만 결과가 있으면 고정된 상한까지 전체 목록을 유지합니다.

작업 트리에서 `Shift-Enter`를 누르면 현재 창을 바꾸는 대신 새 분할 창에서 엽니다.

검색어가 기존 작업 트리와 일치하지 않으면 팔레트에 입력한 텍스트를 이름으로 사용하는 **`Create worktree`(작업 트리 만들기)** 행이 표시됩니다. 기존 일치 항목이 먼저 선택된 상태로 유지되므로 실제 결과가 있을 때 `Enter`를 누르면 계속 해당 항목으로 이동합니다.

바로가기 바인딩은 [설정 → 바로가기](/orca-docs-ko/docs/settings/)에서 다시 매핑할 수 있습니다.
