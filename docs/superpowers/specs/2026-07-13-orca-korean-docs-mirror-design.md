# ORCA 한국어 문서 미러 설계

## 1. 목적

`https://www.onorca.dev/docs` 아래의 공개 문서를 한국어로 제공하는 비공식 미러 사이트를 구축한다. 원본 문서의 페이지 구성, 탐색 순서, 표, 코드, 링크, 이미지가 한국어 사이트에서도 빠짐없이 표시되어야 한다. 원본 변경 사항은 평일 오전 10시(Asia/Seoul)에 확인하고, 검증에 성공한 변경은 `tz1012/orca-docs-ko`의 `main` 브랜치에 즉시 반영해 GitHub Pages로 배포한다.

이 사이트는 공식 번역으로 오인되지 않도록 모든 문서에 비공식 번역 고지와 원문 링크를 표시한다.

## 2. 확정 요구사항

- 대상 범위는 원본 sitemap에 포함된 `/docs` 경로 전체다.
- 제목, 본문, 표, 안내 상자, 메뉴, 캡션, 이미지 대체 텍스트를 한국어로 번역한다.
- 코드, 셸 명령, 파일 경로, URL, 제품명은 의미가 바뀌지 않도록 보존한다.
- 이미지 파일의 시각적 내용은 번역하거나 편집하지 않는다.
- 원본 이미지의 바이트를 그대로 사용하고 가능한 이미지는 미러 저장소에 보관한다.
- 평일 오전 10시(Asia/Seoul)에 Codex 로컬 자동화를 실행한다.
- 변경이 있으면 검증 후 `main`에 직접 커밋하고 푸시한다.
- GitHub Actions가 성공한 `main` 커밋을 GitHub Pages에 즉시 배포한다.
- 변경이 없거나 검증에 실패한 실행은 커밋하지 않는다.

## 3. 선택한 접근법

### 3.1 선택안

Codex 로컬 자동화가 수집·증분 번역·검증·Git 푸시를 담당하고, GitHub Actions가 정적 사이트 빌드와 GitHub Pages 배포를 담당한다. 사이트는 Astro Starlight 기반으로 생성한다.

이 방식은 별도 번역 API 키와 API 사용료가 필요 없으며, 문서 사이트에 필요한 탐색 메뉴, 검색, 이전/다음 이동, 반응형 레이아웃을 정적 파일로 제공할 수 있다. 예약 실행 시 Windows PC와 Codex 로컬 실행 환경이 사용 가능해야 한다.

### 3.2 검토한 대안

1. GitHub Actions에서 번역 API까지 호출하는 방식은 PC와 무관하게 동작하지만 별도 API 키, 사용료, 비밀 값 관리가 필요하다.
2. 원본 HTML을 통째로 복제한 뒤 텍스트 노드를 치환하는 방식은 외형을 더 가깝게 만들 수 있으나 원본 Next.js 내부 구조 변경에 취약하고 검색, 링크, 번역 단위 관리가 불안정하다.

## 4. 시스템 구성

### 4.1 원본 수집기

수집기는 다음 책임만 가진다.

- `https://www.onorca.dev/sitemap.xml`에서 `/docs` URL을 추출한다.
- 각 URL의 HTTP 상태와 최종 URL을 확인한다.
- 문서의 본문, 제목, 섹션 구조, 표, 목록, 안내 상자, 코드, 링크, 이미지와 탐색 순서를 의미 단위로 추출한다.
- 광고성 공통 헤더와 푸터처럼 문서 콘텐츠가 아닌 요소를 제외한다.
- 정규화된 원문 블록마다 안정적인 식별자와 SHA-256 해시를 만든다.

수집기는 원본 문서를 저장소에 그대로 복제하지 않는다. 번역 재사용과 변경 감지에 필요한 URL, 블록 식별자, 해시, 확인 시각, 이미지 메타데이터만 매니페스트에 기록한다.

### 4.2 증분 번역기

번역기는 원본 블록과 기존 매니페스트를 비교해 새 블록과 변경된 블록만 번역한다. 변경되지 않은 번역은 재사용한다. 페이지 이동이나 메뉴 순서 변경은 콘텐츠 번역과 분리해 처리한다.

번역 규칙은 다음과 같다.

- 기술 문서형 `~합니다` 문체를 사용한다.
- Orca, Codex, Claude Code 등 제품명은 원문 표기를 유지한다.
- 실제 애플리케이션의 영문 UI 라벨은 `` `Create branch`(브랜치 만들기) `` 형식으로 원문과 한국어를 함께 표시한다.
- 코드 블록, 인라인 코드, 명령어, 플래그, 파일 경로, 환경 변수, URL은 번역하지 않는다.
- Markdown과 HTML 구조, 링크 목적지, 표의 행과 열 관계를 보존한다.
- 이미지 내부 문자는 번역하지 않으며 캡션과 대체 텍스트만 번역한다.
- 의미가 불확실한 용어는 임의로 삭제하거나 축약하지 않고 원문 용어를 병기한다.

### 4.3 한국어 정적 사이트

Astro Starlight는 생성된 한국어 Markdown/MDX를 읽어 정적 사이트를 만든다.

- 원본의 문서 분류와 좌측 탐색 순서를 반영한다.
- 모든 내부 문서 링크를 한국어 미러 경로로 다시 쓴다.
- 외부 링크는 원본 목적지를 유지한다.
- 페이지별 이전/다음 링크와 전체 문서 검색을 제공한다.
- GitHub Pages의 저장소 하위 경로에서도 CSS, JavaScript, 이미지 링크가 올바르게 동작하도록 base path를 적용한다.
- 모든 페이지 상단에 비공식 번역 고지, 원문 URL, 마지막 원문 확인 시각을 표시한다.
- 사이트 푸터에 원본 문서와 이미지의 권리가 Lovecast Inc. 및 각 권리자에게 있음을 표시한다. 미러의 수집·번역 도구에 적용하는 라이선스가 원본 콘텐츠와 이미지에 적용되는 것으로 표현하지 않는다.

고지의 기본 문구는 다음과 같다.

> 이 문서는 ORCA 공식 문서의 비공식 한국어 번역입니다. 내용이 다를 경우 원문이 우선합니다.

### 4.4 이미지 저장소

문서에 포함된 이미지는 콘텐츠 해시로 중복을 제거하고 원본 바이트 그대로 정적 자산 디렉터리에 저장한다. 이미지 경로가 바뀌어도 내용이 같으면 기존 파일을 재사용한다.

원본 `robots.txt`가 자동 수집을 제한하는 `/docs/*.gif` 등의 자산은 다운로드하지 않는다. 해당 자산은 원본 URL을 사용해 페이지에 표시한다. 이 예외는 매니페스트에 기록하고 링크 유효성을 검사한다.

## 5. 동기화 데이터 흐름

1. 평일 오전 10시에 Codex 로컬 자동화가 저장소에서 동기화 작업을 시작한다.
2. 수집기가 sitemap과 각 문서를 가져온다.
3. 정규화된 URL 집합과 블록 해시를 기존 매니페스트와 비교한다.
4. 번역기가 새 블록과 변경된 블록만 한국어로 변환한다.
5. 사이트 생성기가 문서, 탐색 구조, 내부 링크, 이미지 참조를 갱신한다.
6. 검증기가 콘텐츠 완전성, 링크, 이미지, 코드 보존, 사이트 빌드를 검사한다.
7. 모든 검사가 성공하고 실제 diff가 있을 때만 자동화가 `main`에 커밋하고 푸시한다.
8. GitHub Actions가 정적 사이트를 다시 빌드하고 GitHub Pages에 배포한다.

원본 sitemap에서 사라진 페이지는 한 번의 관측만으로 삭제하지 않는다. 두 번 연속 실행에서 확인되지 않을 때 한국어 사이트에서도 제거한다. 이동 목적지가 확인되면 가능한 경우 기존 미러 URL에서 새 URL로 리디렉션한다.

## 6. 변경 기록

매니페스트는 최소한 다음 필드를 가진다.

- 원문 URL과 미러 경로
- 원문 페이지 해시
- 블록별 원문 해시와 번역 결과 식별자
- 원본 sitemap의 `lastmod`
- 마지막 확인 시각과 마지막 번역 시각
- 페이지 누락 연속 횟수
- 페이지 상태: 활성, 삭제 대기 또는 리디렉션
- 이미지 원본 URL, 로컬 경로, 콘텐츠 해시, robots 예외 여부

자동 커밋 메시지에는 실행 날짜와 추가·수정·삭제된 페이지 수를 기록한다. 변경이 없으면 커밋을 만들지 않는다.

## 7. 오류 처리와 안전장치

- sitemap 또는 다수 페이지를 가져오지 못하면 전체 동기화를 실패로 처리한다.
- 일부 페이지의 구조를 해석하지 못하면 해당 실행에서 푸시하지 않는다.
- 번역 결과가 비어 있거나 코드 구조가 바뀌면 푸시하지 않는다.
- 이미지 다운로드 실패나 내부 링크 단절이 있으면 허용된 외부 이미지 예외가 아닌 한 푸시하지 않는다.
- 실패한 실행은 기존 `main`과 배포 사이트를 수정하지 않는다.
- 로컬 자동화 실행 기록에 단계, URL, 오류 원인을 남긴다.
- GitHub 자격 증명과 로컬 토큰은 저장소 파일이나 로그에 기록하지 않는다.

## 8. 검증 전략

### 8.1 단위 검증

- sitemap URL 필터링과 정규화
- 본문 블록 추출과 안정적인 식별자 생성
- 코드와 인라인 코드 보호
- 내부 및 외부 링크 재작성
- 이미지 중복 제거와 robots 예외 처리
- 매니페스트 diff와 두 번 연속 삭제 정책

### 8.2 통합 검증

- 샘플 문서에서 제목, 표, 목록, 안내 상자, 코드, 이미지가 보존되는지 확인한다.
- 새 페이지, 수정 페이지, 이동 페이지, 삭제 페이지 시나리오를 고정 fixture로 재현한다.
- 변경된 블록만 번역 대상으로 선택되는지 확인한다.
- 생성된 활성 페이지가 현재 sitemap URL과 일치하는지 확인한다. 삭제 대기 페이지는 활성 페이지 수에서 제외해 별도로 검증한다.

### 8.3 배포 전 검증

- 모든 원문 블록에 대응하는 번역이 존재한다.
- 코드 블록과 명령어가 원문 기준으로 변형되지 않았다.
- 내부 링크와 로컬 이미지가 모두 유효하다.
- 모든 페이지에 고지, 원문 URL, 확인 시각이 있다.
- 검색 색인 생성과 프로덕션 정적 빌드가 성공한다.

초기 구축이 완료되면 전체 문서를 한 번 수집·번역·검증해 첫 배포를 수행한다. 이후 예약 작업은 같은 검증 절차를 거치는 증분 동기화만 수행한다.

## 9. 저장소와 자동화

- GitHub 저장소: `tz1012/orca-docs-ko`
- 공개 범위: public
- 기본 브랜치: `main`
- 게시 방식: GitHub Pages와 GitHub Actions
- 동기화 실행기: Codex 로컬 자동화
- 일정: 월요일부터 금요일까지 오전 10시, `Asia/Seoul`
- 반영 방식: 검증 성공 시 `main` 직접 푸시 및 즉시 배포

로컬 자동화는 PC와 Codex 실행 환경을 사용하므로 예약 시각에 PC가 켜져 있어야 한다. GitHub Pages 배포는 푸시 이후 GitHub에서 독립적으로 실행된다.

## 10. 범위 밖 항목

- `/docs` 바깥의 홈페이지, 다운로드, Enterprise, Changelog 번역
- 이미지나 애니메이션 내부 문자 번역
- 원본 사이트의 비공개 소스 코드 또는 픽셀 단위 디자인 복제
- 원문 문서의 내용 수정이나 공식 저장소로의 역기여
- 사람이 승인해야만 배포하는 PR 워크플로

## 11. 완료 기준

- sitemap의 `/docs` 페이지 전체가 한국어 미러에서 탐색 가능하다.
- 메뉴, 본문, 표, 캡션, 링크 설명이 한국어로 제공된다.
- 코드, 명령어, 경로, 이미지가 의미나 내용 변경 없이 표시된다.
- 각 페이지에 비공식 번역 고지와 원문 링크가 있다.
- 평일 오전 10시 자동 실행에서 변경된 콘텐츠만 번역한다.
- 검증 성공 시 `main`과 GitHub Pages가 자동 갱신된다.
- 변경이 없거나 오류가 있으면 기존 사이트가 그대로 유지된다.
